### F1 — `Σ` and empty-column atoms (major, fixed)

- **Defect.**
  - The drafted `kerSigma sd rd (e, μ, q) = (e + 2δ, μ, shiftVal r d q)` shifts the third
    coordinate of every atom.
  - For an empty-column atom `(2e, 0, 0)` that coordinate is a dummy `0`, which `T_{r,d}` does not
    change.
  - When `r = 0`, `shiftVal 0 d 0 = d`. Then `word_kernel` (`w(F_E X) = P ++ Σ(w X)`) fails for
    every `X` that has an empty column.
- **Instance:** `E = L_1 = [[],[(0,∅)]]` (root `0`, `d = 1`) and `X = [[],[]]`.
  - `F_E(X) = [[],[],[]]`, so `w(F_E X) = (0,0,0)³`.
  - The drafted `P ++ Σ(w X)` is `(0,0,0),(0,0,1),(0,0,1)`.
- **Where it occurs.** Roots `r = 0` and targets with empty outer columns both occur among standards
  (for example `L_1[n] = [[],[],…,[]]`).
- **Consequence.** `word_kernel` feeds `kerIter`, which T3.8b, T3.8f and therefore all of cofinality
  use.
- **Fix.** `Σ` fixes the third coordinate when the depth coordinate is even and the marker is `0`, and
  applies `shiftVal r d` otherwise.
  - The Lean definition and D3.3 item 4 are changed; the D3.3b proof now argues block by block.
  - REQ-U1-18 is corrected the same way: relabelling acts on entry atoms only.
  - The corrected `Σ` is strictly monotone on all of `WordAtom`: blocks `(e, μ)` map to blocks
    `(e + 2δ, μ)`, and inside a block it is the identity or `shiftVal`.
- **Tests:**
  - drafted `Σ`: 11,979 failures in 117,948 cases on standards, and 33,616 failures in 45,684 cases on
    random V,I inputs;
  - corrected `Σ`: 0 failures in all 163,632 cases;
  - strict monotonicity: checked on a 50-atom box for `(r,d) = (1,2)` and `(0,3)`, with 0 failures.

### F2 — the parameter-0 ordinary output (major, fixed)

- **Defect.** D3.3a part 1 (`expand_eq_iterate`) assumes `KernelDefined`, and part 2 only says when
  the result is `none`. No lemma gave `expand E 0 = some (C_E ∅)` when the owner root is exhausted. Three
  proofs that assume only V, I cite D3.3a at `n = 0` (they need it without `KernelDefined`):
  - T3.2g (`expand_safePrefix`);
  - T3.2 step 5 (`expand_lt`, which the spine contract states for V, I only);
  - T3.8c.3.
- **Instance with `¬KernelDefined`, checked with the locked Lean `expand` by `#eval`**
  (`scratch/blueprint/U2-verify/eval_exhausted.lean`):
  - `E = [[],[(0,H)]]`, `H = [[(1,∅)],[(2,G),(1,∅)]]`, `G = [[(3,∅),(3,∅)]]`;
  - V and I hold, the step is ordinary, and the owner root `1` is exhausted;
  - `expand E 0 = some [[],[(0,[[(1,∅)]])]] = some (C_E ∅)`, while `expand E 1 = none` and
    `expand E 2 = none`.
- **Fix.** New D3.3a part 3, Lean `expand_zero_eq_context` (hypotheses `E ≠ ∅`, V, I, ordinary,
  `stopData`; no `KernelDefined`). Its proof is REQ-U1-1 with `ordZ … 0 = ∅`. T3.2g, T3.2 step 5 and
  T3.8c.3 now cite it.
- **Tests:** the `n = 0` identity held in 9,829 cases on standards and 3,807 random V,I ordinary
  inputs, plus the instance above.

### F3 — owner flags in `root_fixed_cursor` (major, fixed)

- **Defect.** The draft claimed `rdN.owner = rdO.owner` for the new cap `K` and the old cap
  `K' = litCap A a k ρ` when `ρ ≤ r`. This is false when:
  - `ρ = r`;
  - the cut lies inside a restored origin `u`.
  Then the old cap's root `R` contains the cut, so it is the owner. In `B` the cut lies in the head and
  `R` is an earlier column, so it is not.
- **Instance:** `A = [[],[(0,[[(1,∅)]])],[(1,∅),(1,∅),(1,∅)]]`, `n = 2`, layer 1, `a` = the column
  inside `R[0]`, `k = 1`, `ρ = 1`. The new root data is `(0,1,⟨[],1⟩,false,0)` and the old is
  `(0,1,⟨[],1⟩,true,0)`.
- **Tests:** 106 failures in 3,827 cases. All 106 have `ρ = r`, an owner old root and a non-owner new
  root. The cursor and the root column agreed in all 3,827 cases.
- **Fix.** The conjunct is dropped from the Lean statement and the doc. T3.8lr and T3.8ls use only the
  cursor and the root column, through the filling identity (1). That identity is uniform in the owner
  flag (tested: 163,632 cases, 0 failures).

### F4 — `head_path_rev` needs the decorated system of `B` (major, fixed)

- **Defect.** The draft concluded a path in `B` for `actualKeys B`.
  - In the owner case the last restored key of a head is a continuation key.
  - That key is strictly smaller than the κ-fixed old root key, and the image query can consume it.
    Then the scan is exhausted and the copied edge disappears.
- **Instance:** `A = [[],[(0,[[(1,[[(2,∅),(1,∅)]])]])]]`, `n = 1`.
  - Take the template column of number 2 and `W = B_a(0)` (a cut query of that column).
  - In `A` the old path `1 → 0` exists.
  - In `B`, the head `s_1 = 3` has actual keys `[(), h_3([[(3,∅)]])]`. Both are consumed by `κ_1 W`, so
    the scan is exhausted.
- **Fix.** The conclusion now reads in `capKeys B (routeCols B)`. That is exactly T3.2r's target ("target
  decorated A of `B`", then `capping_iff`). The doc's proof step 4 explains the trace-fact (2) step at
  decorated heads.
- **Tests** (`test_headpath.py`):

  | `A → B` (fixed) | actual → decorated | own cut queries | 9,348 | 0 |
  | `A → B` (fixed) | actual → decorated | larger pool | 22,392 | 0 |
  | `A → B` | decorated → decorated | own cut queries | 9,420 | 0 |

### F7 — the I step of the projection (minor, fixed)

- **Defect.** For a column `a` of the root forest after the root, with `δ > 0`, the copy in `B` lies
  in the stopping forest. Its host there is not the image of `host(a)`.
- **Fix.** The draft's step is replaced by a two-case argument:
  - root-forest columns, where `h_a < r`;
  - columns in heights of columns numbered `≥ r`, where `h_c = h_a + φd`.
- The conclusion (I of `K'`) held in all 32,183 bounded projection cases.

### F8, F9 (minor, fixed)

- **F9.** L3.5c's correspondence between `w(rt(D))` and a suffix of `w(D)` is now stated separately for
  `γ < |R|` and `γ = |R|`. In the second case the empty first column adds one marker atom.
