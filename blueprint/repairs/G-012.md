### 2.5 False statements: the coordinates of "no move inside `B`"

**The statements.** The blueprint writes "no move lies inside `B`" as
`hout : ∀ m ∈ w.moves, ¬ b.heightPath <+: m.col.path`. It appears in:
- U2 D3.1e `moves_spec` and `applyMoves_litCap_addr` (hypothesis);
- U3 L7.5a `frame_repair` (hypothesis);
- U3 L4.3c `repair_moves_outside` (conclusion).

**The coordinate mismatch.**
- Move `idx` acts on `applyMoves (litCap …) (w.moves.take idx)`, so its column is written in the
  coordinates of that expression.
- `b` is the address in `E`. After an outer move has relocated `b` to
  `b_idx := moveAddr (w.moves.take idx) b`, a later move inside the current height `B_idx` can have
  a column path that does not extend `b.heightPath`. `hout` then holds although the move is inside
  `B`.

**Counterexample.** Checked by `#eval!` on the real Lean bodies:
`scratch/blueprint/repairs/G-012/cex_tail.lean`, output `cex_lean.txt`. Python cross-check:
`cex_hout.py`.
- The expression. `H₁ := [[(1,[[(2,∅)]]), (1,[[(2,∅)]])]]` and `E := [[], [(0,H₁), (0,H₁)]]`.
  `E` is standard: size 18, seed `L_4`, parameters `1,1,1,1,1,0,1,2,1,1,1,1,0,0,1`.
- The cap. `w := (c, k, p, ms)` with:
  - `c = ⟨[(1,1),(0,1)], 0⟩`, the only column of the height of `H₁`'s second entry, inside the
    second outer entry;
  - `k = 1`, `p = 0`;
  - `ms = [⟨⟨[],1⟩, 0, 1⟩, ⟨⟨[(1,0)],0⟩, 0, 1⟩]`.

  `IsUpward` holds. Each move satisfies `MoveOK`: its last entry `j = 1` contains the current stop,
  the parents agree, and `H₀ < C`. The final `w.H = [[], [(0, [[(1, [[(2,∅),(0,∅)]])]])]]` is in L.
  So `w : AdmCap E`.
- The marked entry. `b = ⟨⟨[],1⟩, 1⟩`, so `b.heightPath = [(1,1)] <+: c.path`.
- `hout` holds. The move columns have paths `[]` and `[(1,0)]`, and neither extends `[(1,1)]`.
- But move 1 lies inside the current height. After move 0, `b_1 = ⟨⟨[],1⟩, 0⟩`, and
  `b_1.heightPath = [(1,0)] <+: [(1,0)]`. So `MovesOutside ms b` fails.
- Conclusions that fail (Lean output):
  - `applyMoves_litCap_addr` at `q = 2`: `applyMoves K ms = litCap E c' 1 0` with
    `c' = ⟨[(1,0),(0,1)], 0⟩` is **false**;
  - `moves_spec` item 4: `(applyMoves (E.truncAfter b) ms).heightAt bm = E.heightAt b` is
    **false**;
  - `moves_spec` item 1: `RepairList (E.truncAfter b) b ms` is **false**. At `idx = 1` the move
    column `⟨[(1,0)],0⟩` is neither `b_1.col = ⟨[],1⟩` nor a container column of it.
- `frame_repair`'s conclusions hold in this example. No counterexample to them was found (§6.4),
  but the plan's proof of `frame_repair` rests on the two false U2 statements.

**Why earlier tests missed it.** The U3 verifier's model applies the repair inside out: inner
moves come first, while `b` is still at its original address, and there `hout` is exact. The
`MovesValid` body allows every order. G-012 enumerates all orders (§6.2).

**The corrected statements** (Lean in `G012.lean`).

```lean
def Closure.MovesOutside (ms : List Move) (b : EntryAddr) : Prop :=
  ∀ idx (h : idx < ms.length), ¬ (moveAddr (ms.take idx) b).heightPath <+: (ms[idx]).col.path
```

- `Closure.moves_spec_cur`, `Closure.applyMoves_litCap_addr_cur` and `Packet.frame_repair_cur`:
  the original conclusions, with `hout : MovesOutside w.moves b`.
- `Packet.repair_moves_outside_cur`: under the original record hypotheses, the conclusion
  `MovesOutside w.moves rk.b`.

**Why the existing proofs prove the corrected statements.**
- **U2 D3.1e proof item 5 (`moves_spec`)** argues: "by `hout` no move lies inside the height of
  `b`, so each move is in `b`'s column or in a strict container column of `b`, and its retained
  entry `j` … is `b` or `b`'s container". This is about `b`'s *current* column, which is
  `MovesOutside`.
- **D3.1e proof item 6 (`applyMoves_litCap_addr`)** is an induction on `q` in which "a move outside
  the height of `b` relocates `b`'s container chain". That also uses current coordinates.
- **U3 L4.3c steps 1-5** take "the first move inside `B`" and work with `b_idx` and
  `X.heightAt b_idx`. Read with `b_idx`, they derive a contradiction from a first move inside the
  current height, which proves `MovesOutside`.
- **`frame_repair_cur`** is proved in Lean from the corrected U2 statements (§4.5).

**Strength.** `MovesOutside` implies the blueprint's `hout`.
- Every move column `m.col` with `⟨m.col, j⟩` containing the current stop is comparable with
  `b_idx.heightPath`: both are prefixes of the stopping column's path.
- So `MovesOutside` forces `|m.col.path| < |b.heightPath|`, and hence the original `hout`.

The corrected L4.3c is therefore stronger than the original, and the corrected U2 and L7.5a
lemmas are weaker. Their consumers supply `MovesOutside`, through L4.3c (corrected).

**Other consumers.** These are stated under record hypotheses (`hadm`, `hfd`, `hw`) and stay true:
- L4.3b `marked_height_mono`;
- L4.3 `repair_output`, `repair_output_exists`, `query_size_bound`;
- L7.5 `joint_repair`.

Their proofs cite L4.3c, R12 and R18; read with the corrected statements, they are unchanged.
