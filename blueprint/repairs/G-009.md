# G-009 — the response at a previous-phase root (U2 T3.8lo, OP-U2-1)

**Gap:** G-009. **Owning unit:** U2 (`BTBMS.Closure`). **Node:** T3.8lo, in the T3.8l ordinary-step
block of `blueprint/U2-closure-cofinality.md`. **Paper:** txt:520-560, in particular txt:553-560;
the detour argument it compresses is txt:389-393 and txt:526-530.
**Lean:** `blueprint/repairs/lean/G009.lean`, appended after `blueprint/lean/U5.lean` in the
integrated check. **Scratch:** `scratch/blueprint/repairs/G-009/`.

**Outcome.** The missing invariant is G9.5 (`Closure.low_head_detour`, with its edge form
`Closure.detour_copy`). Once `s_h` is low, the cut path of the cap from `s_h` is, edge by edge, the
`τ_{h−1}`-copy of the old terminal-to-root path. That old path is read at the query
`W_h = κ_{φ−h+1}W`, with `V = κ_{h−1}W_h`, and it ends at `s_{h−1}`. An edge at a copy that contains
the cap column is kept by the cut barrier of the cap `K`. With this invariant, T3.8lo follows from:
the phase exit through `s_φ` (G9.8a), lowness at every head (G9.7, from T3.8lm), and the fact that
paths are orbits (G9.2f). T3.8lo needs one extra hypothesis: `hend : capPos B c k < µ(B)`. This
hypothesis is already available at T3.8lo's only use, T3.8lp. The derivation no longer uses T3.2q,
so OP-U2-2 does not affect T3.8lo.

Every statement below that is decidable on concrete forests was tested on the bounded pools of §5,
and all of them passed with 0 failures. The tested pools include:

- 18,427 non-full previous-phase caps of standard expressions (the original test had 647);
- 94,402 such caps of random ordinary expressions in L;
- 1,185,545 low-head detours checked edge by edge.

The Python port was checked against `#eval!` of the real Lean bodies:

- on 94 caps, where every summary agreed;
- on the auxiliary statements, where every `(cases, failures)` count agreed. The address laws were
  checked exhaustively in Lean.

## 1. The problem

`blueprint/U2-closure-cofinality.md`, lines 1778-1798 (as committed at 133f5d8):

> ### T3.8lo The response at a previous-phase root   (paper: txt:553-560)
> **Fidelity:** as in paper (compressed in the paper; see Open problems OP-1).
> **Statement.** `prev_root_response`: with `r < ρ < s_φ` and `K` an upward L cap of `B` at `phaseCol i a`:
> the unconsumed root suffix of `K` is `u :: us` with `u.1 ≥ r`.
> **Proof.**
> 1. `K`'s final test is a path at `V = κ_φ(W)` from a phase-`φ` vertex to `ρ`. Leaving phase `φ` goes
>    through the head `s_φ` or below `r` [T3.8ln]; below `r` it cannot return above `r` (V). At `s_φ` a
>    high response is `R`'s response `< r` [T3.2q step 2]; so `s_φ` is low and the path enters phase
>    `φ − 1` along the copy of the old terminal-to-root path.
> 2. Every later head `s_h`, `1 ≤ h < φ`, compares `V` with `κ_{h−1}(Z)`; by T3.8lm the sign is the same
>    as at `s_φ`: low.
> 3. If `ρ` is a head `s_h`: its response is a query parent `τ_{h−1}(q) ≥ r`. If `ρ` is a phase-`h` body
>    column `x + hd`: it lies on the copied terminal-to-root path, its response at `V` is that path's next
>    vertex (sign independence relates the comparison of `V` with `κ_h(x`'s keys`)` to the old one), a
>    column in `[r, t)` copied to `[s_h, s_{h+1})`, so its parent is `≥ r`. Capping an unconsumed owner key
>    does not change this actual response [trace fact (2)].
> **Uses:** T3.8ln, T3.8lm, T3.2q.

The open problem, line 1971 (OP-U2-1), also `blueprint/INTEGRATION.md` line 214 and
`blueprint/verification/U2.md` O1:

> The paper's argument for "the response at a previous-phase root is a parent `≥ r`" (txt:553-560) is
> compressed. Step 3 (a body-column root's response equals the next vertex of the copied
> terminal-to-root path) needs an explicit invariant relating `V = κ_φ W` to the old terminal queries
> along the low-head detour. [...] 647 caps with `r < ρ < s_φ`, 0 failures [...]; the proof-level
> invariant is still open.

Paper, txt:553-560:

> If r < ρ < s_i, a path reaching this previous-phase root must leave the current phase through a
> low head. A high exit would fall below r. In comparisons of the fixed κ_i W with κ_h Z, h < i,
> moving false fields of the latter lie in [s_h, s_{h+1}), below s_i, whereas moving false fields of
> the former are at least s_i. [...] Every reached positive head is low. At a proper previous root its
> next parent on the terminal-to-root path is at least r; the same holds at a previous head. Capping
> an unconsumed owner key does not change this actual response.

**What exactly is missing.**

1. *The query of the copied path.* Step 3 does not say at which old query the "copied
   terminal-to-root path" is read. The path is read at `W_h = κ_{φ−h+1}W` in the `h`-th detour. A
   detour vertex `x + (h−1)d` compares `V = κ_{h−1}W_h` with `κ_{h−1}` of the old keys of `x`. This is
   trace fact (1) with the common map `κ_{h−1}`. Sign independence (T3.8lm) is needed only at the
   heads. The parenthetical in step 3 assigns it to the wrong comparison.
2. *Copies that contain the cap column.* The copies of the old route containers of the stopping
   column contain `c`. Their active key is a changed continuation in `B` and a truncated key in `K`.
   At these copies the keys are not `κ`-related at the active entry, so trace fact (1) does not give
   the copied edge. Some argument must show that the scan stops at or before the active entry.
   VERIFY-U2 F4 records the same phenomenon at a head's continuation key: there an image query
   consumed the changed key and the edge disappeared. The argument used here is the cut barrier of
   `K` (U1 L2.3c `cut_barrier_read`), applied along `K`'s own cut path. In 126,744 tested detour steps
   the old cursor sits exactly at the active entry, so the barrier alone decides the edge (§5,
   "barrier-critical").
3. *Leaving phase `φ`.* T3.8ln gives the parent dichotomy only for the entries of `c` itself. The
   phase exit needs it for every column of `c`'s stack above `s_φ` (G9.4e).
4. *Putting `ρ` on the copied path.* The cut path to `ρ` and the copied path from `s_φ` to `r` are
   different paths. They are identified because `g_V` is a partial function (G9.2f).
5. *`V = κ_φ W`* fails at full cuts. At the full cut of a route column, `capPos = µ(B)`, the cut
   query contains the changed continuation key. This happened in 1,711 of 1,769 full-cut caps of the
   original pool (§5). The Lean statement of T3.8lo lacks `capPos < µ(B)`.

### G9.5 The invariant

**Low-head detour invariant.** Let `1 ≤ h ≤ φ`. Let `W'` be a reduced query with
`V = κ_{h−1}(W')` and `W' < Z`, so `s_h` is low. Let `j = cursor y W'`. Then the following hold.

- (i) The response of `K` at `s_h` is `τ_{h−1}(q_j)`.
- (ii) Every edge `x → y` of the old orbit `g_{W'}` on the stopping column's stack with `r < x < t` is
  copied in `K` to the edge `x + (h−1)d → τ_{h−1}(y)`. This holds as soon as `K`'s cut path reaches
  `x + (h−1)d`.
- (iii) Hence, if `K`'s cut path reaches `s_h`, it continues from `s_h` to `s_{h−1}`. The segment is
  the `τ_{h−1}`-copy of the old path from `q_j` to `r` at `W'` (G9.3).

In T3.8lo, at the `h`-th head, `W' = W_h = κ_{φ−h+1}W`.

### G9.4s1–s5
- **s1, s2** (`onStack_underCol`, `num_underCol`). Unfold U1's `ColAddr.OnStack`, spine `ColAddr.num`
  and `underCol`. There are two cases.
  - **`b.path = []`.** Then `underCol h b = ⟨h.path, h.col + b.col⟩`. Its own-level columns
    `⟨h.path, j⟩`, `j < h.col + b.col`, are either `h`'s own-level columns (`j < h.col`) or the
    images `underCol h ⟨[], j − h.col⟩`.
  - **`b.path = (c₀,e₀)::rest`.** The levels below `|h.path|` are `h`'s. At level `|h.path|` the
    columns `j ≤ h.col + c₀` split at `h.col` in the same way. The deeper levels and the own level are
    the `underCol h`-images of `b`'s.

  For the numbers, the path sum of `underCol h b` is `sum(h.path) + (h.col + c₀ + 1) + sum(rest)`.
  This is T3.2i proof step 5.
- **s3** (`container_underCol`, `container_underCol_of_onStack`). Unfold spine `ColAddr.container`.
  The path of `underCol h x` is `h.path` followed by the steps of `x`, whose first column is shifted
  by `h.col`.
  - So the prefix-and-column test for `underCol h o` against `underCol h b` is the test for `o`
    against `b`.
  - A column strictly on `h`'s stack meets `underCol h b`'s path at the same level as `h`'s path.
    At its own level its index is `< h.col`, and every step of `underCol h b` there has index
    `≥ h.col`.
- **s4, s5** (`kerCol`). On the root-tail region, `kerCol` (U2 body) strips the prefix `rd.col.path`
  and subtracts `ι = rd.idx` from the first column index. On a first step through the root
  (`(ι, e)`, `e ≥ c_A`) it replaces `e` by `m + e − c_A`. These are strictly monotone index maps,
  applied identically to every address with that prefix, so `OnStack` and `container` are preserved.
  Its range is the set of kernel-output addresses not inside head entries `< m`.
  - The stack columns of a root-tail `x` with number `≥ r` are exactly the region's columns on that
    stack: the root forest's columns `⟨rd.col.path, j⟩` with `j ≥ ι`, and the deeper ones. Columns at
    the levels inside `rd.col.path` have numbers `< r` (`ColAddr.num_lt_of_onStack`). This gives s4
    and `kerCol_of_onStack_tail`.
    - In the owner case the level-`|rd.col.path|` step of `x` is `(ι, e)` with `e ≥ c_A`, so the only
      column there with number `≥ r` is `rd.col`.
    - The deeper columns share that step.
  - The number formula is T3.2i proof step 5.
  - The entry index changes only for the root itself, which gives `container_kerCol`.
  - Q-material `x` (path `sd.col.path ++ (sd.col.col, j)::rest`, `j < m`) maps to `⟨(0,j)::rest, x.col⟩`.
    Its stack is `⟨[],0⟩` (the head) plus the images of the Q-material columns on `x`'s stack. This
    is s5.
  - A non-Q column has no Q-material column on its stack: those lie in Q-heights, and a non-Q column
    is not inside one.

  column. A stack column of `sd.col` is either such a route column, which then contains `sd.col`

- **n** (`colAt_phaseCol_tail`). Take the first column of both sides of `localSuffix_phase` (T3.2i.6,

### G9.4e `stack_parent_dichotomy`
Iterate s1 along `c = underCol sd.col (G^{i−1} b₀)`. The stack of `c` is

```
stack(sd.col) ∪ ⋃_{1 ≤ h ≤ i−1} underCol sd.col (G^{h−1} '' stack(kerHole)) ∪ underCol sd.col (G^{i−1} '' stack(b₀)).
```

Take `o` on it with number `x > s_φ`. The rest of the argument is a case analysis on where `o` lies.

1. **`o` on `stack(sd.col)`.** Then `x < t = s_1 ≤ s_φ`. Excluded.
2. **`o` in layer `h` with `1 ≤ h ≤ i−1`.** By s4, `o = phaseCol h o₀` with `o₀` on `sd.col`'s stack
   and `num o₀ ∈ [r, t)`. Then `x = num o₀ + hd` (s2). `x > r + φd` and `num o₀ < r + d` force
   `h ≥ φ`.
   - For non-Q `a` (`φ = i`) this is impossible.
   - For Q-material `a` (`φ = i − 1`), `h = φ`. If `o₀ = rd.col`, then `x = s_φ`, which is excluded.
     Otherwise G9.4n gives parents `shiftVal r (φd)` of old ones: `< r` or `≥ s_φ`.
3. **`o` in layer `i`.**
   - **Non-Q `a`.** By s4, `o = phaseCol i o₀`. `o₀ = rd.col` gives `x = s_i = s_φ`, which is
     excluded. Otherwise G9.4n gives phase `i = φ`.
   - **Q-material `a`.** By s5, `o` is the head `s_i` or a Q-material copy.
     - The head's parents are `τ_{i−1}(q) ≥ s_{i−1} = s_φ` or restored, `< r` (`colAt_head`).

`sd.col` is never on the stack of a non-Q column: it is the last column of its forest, and only its
Q-heights lie inside it. In `K` the parents are a prefix of `B`'s (G9.4l).
