### 1.1 Why the earlier variant failed

The U2 verifier tested `capKeys B (routeCols B) → capKeys A (routeCols A)`
(`scratch/blueprint/U2-verify/test_headpath.py`). I reproduced both numbers exactly: 37,697 cases
with 74 failures, and 9,420 cases with 0 failures on cut queries
(`scratch/blueprint/repairs/G-010/explore.py`, output `out_explore.txt`). The failures are
diagnosed as follows (`breakdown_old_variant.py`, output `out_breakdown.txt`):

- All 74 are Q-material in the body case, with `W` not a cut query of `a`. There are 37 at
  `φ = 0` and 37 at `φ = 1`.
- **Instance.** `A = [[],[(0,[[(1,∅)]]),(0,∅)],[(1,[[(2,∅)]]),(1,∅)]]`, `n = 2`, `j = 2`.
  - `a` is the column in `Q[0]`'s height, and `W = [h([[(·,∅)]]), h(∅)]`.
  - The path starts at the head `x = s_2 = 3`.
  - In `B` the head of the last layer is a route column. Its capped key is its last, restored,
    key, so the scan stops in the restored part and returns the restored parent `0`.
  - In `A` the route-capped stopping column caps its terminal `(r, ∅)`. The scan returns `r`, and
    `R` (not a route column of `A`) is then exhausted by `W`.
- The two systems cap *different* entries. Neither is what the cap sees.
  - The cap `K = litCap B c k ρ` caps the head at the entry that contains `c` (here the query entry
    `0`).
  - `K'` caps the stopping column at the same entry.
  - With those caps the instance holds.

def phaseImg (sd : StopData) (rd : RootData) (j : Nat) (a o : ColAddr) : Option ColAddr :=
  if o = sd.col then phaseCol sd rd j rd.col

- `activeKeys E c` caps, in every column `o` that contains `c`, the entry through which it contains
  `c`, and drops the later keys. For `K = litCap E c k p` it is `capKeys K (routeCols K)` read back
  in `E` (L-G010.1).
- `PhasePair` covers both uses:
  - the template copies of T3.8li, with `φ = phaseOff j a`, which is `j − 1` for Q-material;
  - the head of layer `j` as the phase-`(j−1)` copy of the old terminal, the "head of layer `i`
    plays the old terminal" of T3.8lb.
- `phaseImg` is the column map between the stacks (T3.2i). The stopping column goes to the head of
  layer `j`. For Q-material and for the head pair, the columns of the stopping column's stack go to
  layer `j − 1` (to themselves when `j = 1`). All other columns go to layer `j`.

## 3. The proofs

Conventions:
- `τ = shiftVal r (φd)`.
- `κ = WithTop.map (kappa r d φ)`. It is strictly monotone on `WithTop Key` (T3.2h.3
  `kappa_strictMono`, with `⊤ ↦ ⊤`).
- Paths are deterministic. `Edge E ks c W x p ↔ respEdge E ks c W x = some p` (U1 `edge_iff`), and
  under V edges decrease (U1 `edge_lt`). `V` of `B` is T3.2k `condV_ord`.

### 3.1 Helpers

- **L-G010.21a.** Induction along `Scan.cursor`. A source letter `⊤` meets a query letter
  `y ≠ ⊤`, so `⊤ > y` and only the query cursor advances. The source never passes `⊤`.
- **L-G010.21b.** Every letter of `ν(l)` is a letter of `l`: induction with U1
  `nu_append_singleton`. Actual keys are coercions `↑k`, never `⊤`.
- **L-G010.21c.** Unfold `underCol` and `ColAddr.resolveAux` (spine D1.2), case `a.path = []` or
  `(c0, e0) :: rest`.
  - Below `num h` the levels of `h.path` and the columns `0 … h.col − 1` of `h`'s forest are
    visited exactly as for `h`.
  - From `num h` on, the placed columns `h.col + j` and the deeper levels are `a`'s, with numbers
    offset by `num h`.
  - This is the address-level fill law of T3.2i proof step 2.
- **L-G010.21d.** U2 L3.1c `word_litCap` gives `w(litCap E c |col| 0) = w(E).take π ++ [atom]`.
  - Since `c ∈ routeCols E` (U1 `mem_routeCols_iff`), every containing column is last in its forest
    with its last entry active, and `c` is the last column. So the cap deletes nothing.
  - `litCap E c |col| 0` is `E` with `(0, ∅)` appended to `c`, and `π = µ(E)`.
  - `hne` is needed. For an empty route column the cap replaces the column's marker atom, and
    `capPos = µ − 1` (22 bounded cases, all of this shape).
- **L-G010.21e.** Unfold `kerCol` (T3.2i.1); it changes only the first steps of an address.
  - Root-tail and `sd.col`: the root column goes to column `0`, at number `0 = r − r`. Its entry
    `u ≥ c_A` goes to head entry `m + u − c_A`. A body column `ι + 1 + z` goes to column `1 + z`,
    at number `1 + z = (r + 1 + z) − r`. Deeper steps are unchanged, so numbers shift by `−r`
    throughout. (`num_0(kerCol a) = num a − r` is T3.2i proof step 5.)
  - Q-material: the stopping column (number `t`) goes to the head (column `0`), its entry `q < m`
    to head entry `q`, numbers shift by `−t`.
- **L-G010.21f.** `B = C_A(F_A^n ∅) = replaceAt 0 0 Z ℓ A` [D3.3a; `expand_eq_iterate`, and
  `expand_zero_eq_context` for `n = 0`]. `replaceAt 0 0` applies the identity shift. It changes
  only the stopping column (replaced by `Z`'s columns at the same position) and, along the route,
  the heights of the last entries above it. Induction on `replaceAt`'s depth argument (T3.2i proof
  step 2, "columns of `C_A Z` off `sd.col`'s subtree are those of `C_A ∅`").

### 3.2 L-G010.1 (bridge), L-G010.2, L-G010.3

**L-G010.1.** Let `K = litCap E c k p`.
1. If `c.resolve 0 x = none`, both sides are `none`.
2. Otherwise let `o` be the column (`OnStack c o`, U1 `resolve_spec`). The structure of `K` comes
   by induction on `c.path` along `litCapAux` (spine D3.1).
   - At a containing level with step `(ci, ei)`, the columns `< ci` are unchanged.
   - Column `ci` is cut after entry `ei`. Entries `< ei` are unchanged, and entry `ei` keeps its
     parent with a truncated height.
   - At `c`'s level, the columns `< c.col` are unchanged.
   - So for `o` with `o.container c = some ⟨o, v⟩`: `K.colAt o` is `E.colAt o` cut after entry
     `v`, with the same parents and the same heights below `v`. Every other `o` on the stack keeps
     its column. (`litCap_spec`, D3.1e, states the parent and height clauses.)
3. `routeCols K` consists of `c` and its containers, by the same induction with U1
   `mem_routeCols_iff`: each kept containing column is last, its active entry is last, and `c` ends
   with `(p, ∅)`.
   - For a container `o`: `capKeys K (routeCols K) o = (actualKeys K o).dropLast ++ [⊤]
     = (actualKeys E o).take v ++ [⊤] = activeKeys E c o`.
   - For a non-container `o`: `o ∉ routeCols K` (U1 `routeCols_visible`: a visible route column
     contains the column), so both sides are `actualKeys E o`.
4. The key lists agree. For a container the cursor is `≤ v` by L-G010.21a (`W` is `⊤`-free), so
   the response reads an entry `≤ v`, with the same parent in `K` and `E`.
5. The path form follows from `edge_iff`.

With `⊤ ∈ W` the cursor can pass the capped key, and `E` has entries that `K` lacks. Hence `hT`
(179,940 bounded cases differ).

**L-G010.2.** `resolve_of_resolve_lt` (U1 D1.2b) gives `c.resolve 0 x = c'.resolve 0 x` for
`x < z`; call it `o`. It remains to show `o.container c = o.container c'` (U1 `container_spec`).
- If `e.heightPath <+: c'.path`, then `<+: c.path`, because `c'` is on `c`'s stack, so `c'.path` is
  a prefix of `c.path`.
- Conversely, let `e.heightPath = o.path ++ [(o.col, v)] <+: c.path`.
  - `o` cannot lie in `c'`'s own forest. That would need `o.col < c'.col`, while `c'` on `c`'s stack
    has `c'.col ≤` the column of `c.path` at that level, which is `o.col`.
  - So `o.path = c'.path.take k₁` with `k₁ < |c'.path|`, and
    `c'.path[k₁] = c.path[k₁] = (o.col, v)`. Hence `e.heightPath <+: c'.path`.

**L-G010.3.** `stopData_spec` (U1 D1.6b) makes `sd.col` the last route column, and `sd.col.path` is
a route path.
- A column `o` on `sd.col`'s stack that contains `sd.col` contains it through the last entry of the
  last column of its forest, so `o ∈ routeCols A`. Both systems give
  `(actualKeys A o).dropLast ++ [⊤]`.
- Any other `o` is not a route column (`routeCols_visible`), and both give actual keys.

### 3.3 L-G010.4 and its parts (the edge copy)

**L-G010.4a.**
- `colAt_phaseCol`'s proof (T3.2i proof step 3) applies to every entry whose height does not contain
  the hole. `OnHoleRoute` was excluded there only because of the last entry.
- `replaceAt` (spine D1.6) shifts the parent of the continuation entry by the same `τ_i` ("ar":
  `changed_entry = (shiftVal p, …)`).
- If `⟨a, v⟩` contains `sd.col`:
  - `v` is the last entry of the last column of `a`'s forest, because `sd.col.path` is a route
    path.
  - In layer `i` the copy contains layer `i + 1`, or the emptied hole when `i = n`.
  - Every containing column on the way is last with a last active entry, since the next layer
    fills the hole at the end of the route.
  - So `c ∈ routeCols B`.

**L-G010.4b.** The proof has three parts.

1. **Stack.** `c = underCol sd.col ((underCol kerHole)^[j'] a₀)`, with `a₀ = kerCol a` (template)
   or `⟨[],0⟩` (head pair), and `j' = j − 1` (T3.2i.1). Apply L-G010.21c once with `h = sd.col`
   (number `t`). Then apply it `j − 1` times with `h = kerHole`, which has number `d` (T3.2i proof
   step 5). Then apply L-G010.21e.
   - Root-tail `a` (`φ = j`): `x + jd − t − (j − 1)d = x − r`, so
     `c.resolve 0 (x + jd) = phaseCol j (a.resolve 0 x)`.
   - Q-material `a` (`φ = j − 1`), `x ≥ t`: L-G010.21e (Q-material form) gives the head
     (`x = t`) or `phaseCol j o`.
   - Q-material, `r < x < t`, `j ≥ 2`: the recursion of L-G010.21c stops at the level where the
     remaining number `x − r` is `< d`. There it reads `kerHole`'s stack:
     `kerHole.resolve 0 (x − r) = kerCol (sd.col.resolve 0 x)` by L-G010.21e for `sd.col`. Also
     `sd.col.resolve 0 x = a.resolve 0 x` (`resolve_of_resolve_lt`, since `a.resolve 0 t = sd.col`).
     Hence `phaseCol (j − 1) o`.
   - Q-material, `r < x < t`, `j = 1`: `c.resolve 0 x = sd.col.resolve 0 x = o`.
   - Head pair: the same two cases with `sd.col`'s own stack.
   - This is `phaseImg`.
2. **Containers.** `underCol` shifts only the column index of its first step, and `kerCol` changes
   only first steps. For a container with number `> r`, the step through it keeps its entry index.
   - Inside `R[u]`'s height the first step is `R` itself, at number `r` (excluded).
   - A body column `(ci, e)` becomes `(ci − idx, e)`.
   - `sd.col`'s step `(sd.col.col, q)` becomes the head's `(0, q)` (Q-material).
3. **Content.** Let `v` be the active index, or all indices for a non-container. The entries
   `< v` of `o` and `o'`, and the parent at `v`, are related by `τ`:
   - closed template copies: T3.2i.4 `colAt_phaseCol`;
   - hole-route template copies: L-G010.4a, whose only changed height is at an entry containing
     `sd.col`. That entry is never strictly before the active entry, because it is the last entry
     and contains `a` as well.
   - the head (Q-material, `o = sd.col`): T3.2i.5 `colAt_head`, whose first `m` entries are
     `τ_{j−1}(Q)`, with active entry `q < m`;
   - phase-`0` copies (`j = 1`): L-G010.21f.

   Keys: `relKey (num o + φd) (τ H) = κ_φ (relKey (num o) H)` (T3.2h.1 `relKey_shift`,
   `num o ≥ r`), and the capped key is `⊤ = κ ⊤`. So
   `activeKeys B c o' = kappaQ φ (activeKeys A a o)`.

**L-G010.4c.** For every pair, `c.resolve 0 r = some rd.col = a.resolve 0 r`:
- `R` is on `sd.col`'s stack (`rootData_spec`);
- `c` lies under `sd.col`'s position (L-G010.21c);
- `a` is in `R`'s subtree, in `R`'s forest after `R`, or under `sd.col`.

Below `r` both stacks are therefore `R`'s (`resolve_of_resolve_lt`).

Containers below `r`. A column `o` with number `< r` contains `a` ⟺ it contains `R` ⟺ it contains
`sd.col` ⟺ it contains `c`, through the same entry:
- `R.path` is a prefix of `a.path` and of `sd.col.path`;
- conversely U1 `contains_of_resolve` with `num o < r`;
- a column before `R` in `R`'s forest contains no template column.

Contents: L-G010.21f, because these columns are outside `sd.col`'s heights. A container's changed
height is at its last, active, entry, so it is dropped by `activeKeys`. Keys are `κ`-fixed by
T3.2h.5 `kappa_fix` (`num o < r`).

**L-G010.4.** Both parts reduce to the parts above:

  `= (parents B o')[cursor (κ ksA) (κ W)]?`.
